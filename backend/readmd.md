# 班级管理系统后端

使用浏览器本地存储的方式存在一定的风险，清除浏览器数据会导致数据丢失，所以增加了可选的系统后端支持。

## 设计理念

- **离线优先**：前端独立运行，数据存储在浏览器 localStorage
- **可选后端**：后端作为数据同步服务，可部署在U盘上便携使用
- **无需联网**：整个系统设计为本地运行（127.0.0.1）

## 两种使用模式

### 模式一：无后端（纯浏览器）
1. 老师打开网页
2. 直接使用系统
3. 数据保存在浏览器本地存储

### 模式二：有后端（U盘便携）
1. 老师插入U盘
2. 启动后端程序（双击运行）
3. 打开网页，在设置页面登录
4. 同步数据到U盘
5. 下课拔走U盘，数据随身携带

## 技术实现

1. 使用 Go 语言作为后端语言
2. 使用 SQLite 作为数据库存储用户信息
3. 使用本地文件夹存储用户相关的配置文件（JSON格式）
4. 后端配置从 config.yaml 读取

## 业务功能

1. 用户首次使用需要注册账号并登录（本地账号）
2. 账号与数据关联（用户只能访问自己的数据）
3. 用户可以同步本地数据到后端（上传/下载）
4. 用户名唯一性校验

## API 接口

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/health` | GET | 健康检查（前端检测后端是否存在） |
| `/api/register` | POST | 用户注册 |
| `/api/login` | POST | 用户登录 |
| `/api/sync/upload` | POST | 上传数据到后端 |
| `/api/sync/download` | GET | 从后端下载数据 |

## 目录结构

```
backend/
├── main.go              # 入口文件
├── config.yaml          # 配置文件
├── go.mod               # Go模块
├── internal/
│   ├── config/          # 配置加载
│   ├── handler/         # HTTP处理器
│   ├── model/           # 数据模型
│   └── store/           # 数据存储
├── data/                # 运行时数据目录（自动创建）
│   ├── users.db         # SQLite数据库
│   └── userdata/        # 用户数据文件夹
└── readmd.md
```

## 使用方法

### 编译

```bash
cd backend
go build -o classScore-backend .
```

### 运行

```bash
./classScore-backend
```

服务将在 http://127.0.0.1:8000 启动

### 配置

编辑 `config.yaml` 可修改端口、JWT密钥等配置。
